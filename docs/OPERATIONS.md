# 운영 안내

비용과 무료 한도, 실기기 확인 항목, 운영 메모, 동의서 사용법, 알려진 제약을 적은 문서입니다. 예전 `README.md` 에 있던 내용을 그대로 옮겼습니다. 로컬 실행과 서비스 설정은 [SETUP.md](SETUP.md) 에 있습니다.

## 개요

반려동물 미용 매장 히스하우스의 예약 신청서와 교육미용 행동 분석 검사지를, 보호자가 폰에서 한 묶음씩 넘기며 쓰는 웹이다. 제출하면 구글 시트에 한 줄이 쌓이고 슬랙으로 답변 전체가 간다. 보호자 로그인·결제는 없고 기록은 구글 시트가 전부다. 사장님 화면(`/admin`, 비밀번호)은 교육미용 동의서를 만들어 보내고 서명받는 데만 쓴다(아래 '동의서'). 차곡노트 백엔드·앱과 연결하지 않는 독립 저장소다. Next.js 16(App Router) · TypeScript · pnpm 으로 만들었다.

흐름은 첫 화면 → 신청서(보호자·반려견·이용 안내 + 고른 서비스별 묶음 + 예약금 안내) → 완료다. 첫 화면에는 예약 신청서만 있다. **검사지는 링크를 받은 사람만 연다**(사장님 결정 2026-10-30, 설계: `docs/superpowers/specs/2026-10-30-survey-link-design.md`). 교육미용이 든 신청이 오면 슬랙 알림 끝에 그 신청의 검사지 링크(`<주소>/survey/{신청 ID}-{서명}`)가 붙는다. 사장님은 예약금 입금을 확인한 뒤 그 링크를 카카오톡으로 보낸다. 링크는 만료되지 않아 몇 번을 열고 닫아도 이어 쓸 수 있다. 제출하면 그 링크는 닫혀 '이미 제출된 검사지예요' 만 보인다. 링크 없이 `/survey` 를 열거나 링크가 틀리면 안내만 보이고 문항은 내려가지 않는다. 검사지는 링크의 신청 ID 로 시트에 쌓여 예약신청 탭과 같은 ID 로 이어진다.

## 비용

외부 서비스 다섯(Vercel·구글 Sheets API·슬랙·공공데이터포털·네이버 메일)을 쓰고, 지금 규모(하루 신청 수십 건, 미용마다 동의서 한 건)에서는 모두 무료다. 표의 마지막 줄(Vercel 이미지 최적화)은 쓰지 않는 기능이다. 아래는 2026-10·11 에 각 서비스 문서에서 확인한 값이다.

| 서비스 | 요금 | 유료로 바뀌는 지점 · 알아 둘 것 |
|---|---|---|
| Vercel Hobby (배포) | 무료 | 약관상 **비상업·개인용**이라 매장 예약 접수는 상업용으로 볼 여지가 있다. 이를 알고 무료로 시작하기로 했다(2026-10-23). 문제가 되면 Pro(사용자당 월 20달러) 또는 Cloudflare Pages 로 옮긴다. 사용 한도(함수 호출 월 100만 건, 전송량 100GB 등)를 넘으면 요금이 붙는 대신 그 기능이 멈추고 보통 30일을 기다려야 한다. |
| 구글 Sheets API | 무료 | 결제 계정을 연결하지 않고 켤 수 있다. 분당 요청 한도가 있다(쓰기·읽기 각각 프로젝트당 300건, 사용자당 60건 — 서비스 계정 하나라 사실상 60건). 신청 한 건이 쓰기 한 번, 검사지는 링크를 열 때와 낼 때 검사지 탭의 신청 ID 열을 한 번씩 읽는다(2026-10-30 추가). 닿지 않는다. 한도를 넘는 요청에는 구글 결제 계정으로 요금을 매길 예정이라고 구글이 밝혔다(2026년 후반). |
| 슬랙 수신 웹훅 | 무료 | 채널당 초당 1건이라 코드가 통 사이에 1초를 쉰다. 슬랙 무료 요금제는 최근 90일의 메시지만 보여 준다. 오래 남길 기록은 시트가 맡는다. |
| 공공데이터포털 '한국천문연구원_특일 정보' (공휴일) | 무료 | 유료 단계가 없다. 계정마다 하루 호출 한도가 있고(활용신청 화면에 나온다), 넘으면 요금 대신 그날 호출이 거절된다. 서버가 올해·내년 두 번을 불러 12시간 동안 다시 쓰므로 하루 4번 안팎이다. 일시적인 실패도 최대 12시간 남는다(그동안 화요일만 막는다). 거절·실패하면 공휴일만 못 막고(화요일은 막는다) 신청은 그대로 받는다(2026-11-03 추가). |
| 네이버 메일(SMTP) | 무료 | 동의서 사본을 `hisshaus` 네이버 메일로 보낸다(2026-11-03 추가). 하루 발송 한도는 공개된 숫자를 찾지 못했다. **유료로 바뀌는 지점은 메일함 용량**이다. 용량이 차면 정리하거나 네이버 메일 용량 확장(유료)이 필요하다. 동의서 PDF 는 한 건 약 113KB(일반 미용)·약 246KB(행동수정 등 세 장 묶음)이고, 메일에 붙으면 base64 로 바뀌어 한 통이 약 156KB·338KB 다(2026-11-03 표본으로 잼, `scripts/consent-sample.mjs`). 한 건은 보관용 받은편지함에 한 벌, 보낸메일함에도 남으면 보관용·보호자 사본의 보낸 메일 두 벌이 더해져 **세 벌**이다. 보낸메일함에 남는지는 아직 확인하지 못해서 최악(세 벌)으로 잡으면 하루 미용 10건·주 6일(1년 약 3,120건)에 1년 약 1.5GB, 한 벌이면 약 0.5GB 다. 네이버 메일 기본 용량은 5GB 로 알려져 있어(블로그 글 기준, 네이버 공식 도움말은 찾지 못했다) 최악이면 약 3년, 한 벌이면 약 10년 쓴다. |
| Vercel 이미지 최적화 | 쓰지 않음 | 첫 화면 사진을 `next/image` 가 아니라 `<img>` 로 쓴다. 이미지 사용량이 생기지 않는다. |

- 신청 한 건이 함수 호출 한두 번이라 하루 30건이어도 월 2천 번 안쪽이다. Hobby 한도에 닿을 규모가 아니다.
- 코드는 Vercel 전용 기능에 기대지 않는다(서버 경로는 `runtime = 'nodejs'`). 함수 한도 30초(`maxDuration`)는 Hobby 에서 허용된다.

## 실기기 확인 항목

지금까지는 크로미움(Playwright, Pixel 7 화면 크기)에서만 확인했다. 공개 전에 폰의 iOS 사파리와 카카오톡 인앱 브라우저에서 아래를 확인한다.

- [ ] 날짜 칸을 누르면 직접 그린 달력이 아래에 펼쳐지고(브라우저 기본 달력이 아니다) 오늘 이전은 흐리게 보이며 누를 수 없다. 고른 날짜가 '2026년 11월 1일 (일)' 꼴로 보인다. 달력 밖을 누르면 닫힌다.
- [ ] 아래 고정 버튼이 키보드에 가려지지 않는다.
- [ ] 브라우저 뒤로 가기가 묶음을 하나씩 돌아간다.
- [ ] 검사지를 제출한 뒤 완료 화면에서 뒤로 가면 '이미 제출된 검사지예요', 한 번 더 뒤로 가면 양식을 떠난다.
- [ ] 마지막 화면의 제출하기를 누르면 아래에서 확인 창이 올라온다. 휴대폰 뒤로 버튼을 누르면 창이 닫히며 앞 묶음으로 돌아간다(창이 떠 있는 채로 남지 않는다).
- [ ] 카카오톡에 링크를 붙였을 때 미리보기(제목·설명·그림)가 나온다. 검사지 링크는 검사지 제목으로 나온다.
- [ ] 아래 고정 막대(다음·신청하기 버튼, 첫 화면의 예약 신청하기)가 아이폰 홈 표시줄과 겹치지 않는다(`viewport-fit=cover` 와 안전 영역 여백).
- [ ] 선택 문항의 단일 선택 칩(예: 2순위 시간대)은 다시 누르면 해제되고, 필수 문항의 칩은 다시 눌러도 그대로다.

## 운영 메모

- 제출 순서는 검증 → 시트 → 슬랙이다. 시트 저장이 실패하면 슬랙도 보내지 않고 보호자에게 "지금은 보낼 수 없어요" 를 보인다(입력은 남아 있다). 슬랙만 실패하면 보호자 화면은 성공이고 기록은 시트에 있으니, 슬랙이 안 온 신청은 시트에서 찾는다.
- 슬랙은 신청서 한 통이다(신청서는 긴 답 두 칸을 3,000자까지 한글로 채워도 한 통이고, `&`·`<` 같은 기호로만 상한까지 채운 드문 경우에만 두 통이 된다). 검사지는 답 길이에 따라 여러 통으로 나뉘고 머리글에 `(k/N)` 이 붙는다. 보통은 한 통에서 세 통이다(긴 답을 문항마다 150자쯤 쓰면 한 통, 300자쯤이면 두 통, 500자쯤이면 세 통). 모든 칸을 글자 수 상한까지 한글로 채우면 12~13통으로 나뉜다. 통 사이에는 1초씩 쉰다.

- **검사지 링크 보내기**: 교육미용 신청의 슬랙 알림 끝 '📋 검사지 링크' 를 예약금 입금을 확인한 뒤 카카오톡으로 보낸다. 링크는 신청마다 하나이고 만료되지 않는다. 보호자가 제출하면 닫힌다. 고칠 내용이 있다고 연락이 오면 사장님이 시트에서 고친다(링크를 다시 열 수는 없다).
- 슬랙에 링크가 없는 신청(이 기능 전에 들어온 교육미용 신청, 신청서 없이 카톡으로만 예약한 손님)은 `pnpm survey:link <신청 ID>` 로 링크를 만든다. 신청 ID 를 주지 않으면 새로 만들어 함께 찍는다(그 검사지는 예약신청 탭에 같은 ID 가 없다). `.env.local` 의 `SURVEY_LINK_SECRET` 이 운영 값과 같아야 운영에서 열린다.
- 링크는 서명으로 지킨다. 보호자가 제출 **전에** 링크를 남에게 넘기면 그 사람도 볼 수 있다(로그인이 없다). 링크가 퍼졌다면 `SURVEY_LINK_SECRET` 을 바꾸고 다시 배포하면 모든 링크가 막힌다. 아직 안 낸 보호자에게는 `pnpm survey:link` 로 새 링크를 보낸다.

## 동의서

교육미용 동의서·계약서를 웹에서 보여 주고 손가락 사인을 받아 PDF 로 남긴다(설계: `docs/superpowers/specs/2026-11-03-consent-signing-design.md`). 사장님 화면은 `<주소>/hisshaus/admin` 이고 `ADMIN_PASSWORD` 로 들어간다. 한 번 들어가면 그 기기에서 30일 동안 로그인이 이어진다. 처음 설정할 때는 사장님 화면 아래 '메일 시험 보내기' 로 보관 메일함에 메일이 오는지 본다.

### 사장님 사용법

- **링크를 만들어 카카오톡으로 보내기**: '신청서에서 만들기' 에서 이름·연락처로 찾아 고르거나, 신청서가 없는 손님(전화 예약·매장 방문)은 '신청서 없이 새로 만들기' 를 누른다. 문서 묶음 다섯 중 하나를 고르고 그 묶음의 칸만 채운다(행동수정 트레이닝: 프로그램 명·수업 목표, 신뢰쌓기: 수업 시간, 교육 중단 미용 동의서·일반 미용: 미용 부위). 보호자 정보는 신청서 값으로 채워져 있고, 고치면 고친 값으로 보호자에게 보인다. '링크 만들기' → '링크 복사' 로 복사해 카카오톡으로 보낸다. 링크는 만료되지 않고 서명하면 닫힌다. 칸을 잘못 채웠으면 최근 동의서 목록에서 '취소' 하고 새로 만든다(서명한 동의서는 취소되지 않는다).
- **서명되면**: 슬랙에 '동의서 서명' 알림이 오고(보호자가 고친 값과 메일 결과가 함께 온다), 보관 메일함(`MAIL_ADDRESS`)과 보호자 메일로 PDF 가 한 통씩 간다. 보호자는 완료 화면에서도 PDF 를 내려받는다.
- **매장에서 아이패드로 받기**: 링크를 만든 화면이나 최근 동의서 목록의 '서명 대기' 동의서에서 '이 기기에서 바로 서명' 을 누른다. 로그인은 그대로 둔 채 그 기기가 잠기고 서명 화면이 열린다. 아이패드를 보호자에게 건넨다. 잠긴 동안에는 뒤로 가기·주소창으로 사장님 화면에 가도 '잠겨 있어요'(PIN 화면)만 보인다. 서명이 끝나면 '기기를 사장님께 돌려주세요' 화면에서 멈춘다. 돌려받으면 '사장님 화면으로' 를 누르고 `ADMIN_PIN`(4자리)을 넣어 푼다. PIN 을 5번 틀리면 그 기기의 로그인이 풀려 비밀번호부터 다시 넣는다. PIN 은 이미 로그인한 기기의 잠금만 풀고 로그인에는 쓰지 못한다.
- **메일 다시 보내기**: 메일이 실패하면 슬랙 알림의 메일 줄과 최근 동의서 목록에 '실패' 가 보인다. 그 동의서의 '메일 다시 보내기' 를 누르면 시트 기록(칸 값·사인·서명 시각)으로 PDF 를 다시 만들어 실패한 통만 다시 보낸다(보관용만 실패했으면 보관용만, 사본만 실패했으면 사본만, 메일 결과가 시트에 없으면 두 통). 결과는 전에 보낸 통과 합쳐 '다시 보냈어요: 보관 보냄 · 사본 보냄' 처럼 한 줄로 보인다. 다른 화면에서 먼저 다시 보내 두 통 다 갔으면 아무것도 보내지 않고 '이미 두 통 다 보냈어요.' 가 뜬다. 다시 만든 PDF 는 서명 때와 내용이 같아 서명 내용 고유값도 같다. 메일 결과가 시트에 남지 않은 서명(응답이 끊긴 경우 등)에도 버튼이 뜬다. 최근 동의서 목록에는 30건만 보이고, 메일을 다시 보내야 하는 서명은 30건 밖의 것까지 그 아래 '메일을 다시 보내야 하는 서명' 칸에 모두 보인다(없으면 칸이 없다). 원본 PDF 를 바꿨거나 시트의 서명 줄 값을 고쳐 다시 만든 PDF 가 서명 때와 다르면 보내지 않고 '원본 문서나 시트 기록이 서명 때와 달라 다시 만들 수 없어요.' 가 뜬다.
- **메일함 정리**: 보관 메일함 용량은 위 비용 표의 '네이버 메일' 줄을 본다(메일 한 통 약 156KB·338KB, 최악이면 1년 약 1.5GB, 기본 5GB 로 약 3년). 용량이 차기 전에 오래된 동의서 메일을 PC 로 내려받아 보관하고 메일함에서 지운다. 네이버로 보낸 메일이 보낸메일함에도 남는지는 아직 확인하지 못했다. 남는다면 보낸메일함의 동의서 메일(보관용·보호자 사본)도 같이 정리한다.
- **5년 보관**: 서명 화면의 개인정보 안내대로 서명일부터 5년 보관한다. 자동으로 지우지 않는다. 5년 지난 동의서는 사장님이 메일함의 그 메일과 시트 '동의서' 탭의 그 동의서 ID 줄(준비·취소·서명·메일)을 직접 지운다.

### 시트 '동의서' 탭

줄을 붙이기만 하는 기록장이다. 만들 때 '준비', 취소하면 '취소', 서명하면 '서명', 메일을 보내면 '메일' 줄이 쌓이고, 사장님 화면은 같은 동의서 ID 의 줄을 합쳐 상태를 보인다. 줄을 고치거나 지우면 상태가 바뀌므로(서명 줄을 지우면 링크가 다시 열린다) 5년 지난 줄을 지울 때 말고는 손대지 않는다. 서명 줄에는 PDF 를 다시 만드는 데 필요한 값이 모두 있다(맨 끝 '사인' 열은 사인 선의 좌표 글). 메일함이 가득 차거나 메일이 사라져도 이 기록이 마지막 보루다.

### 원본 PDF 와 장 그림

- 원본은 `content/consent-agreement.pdf`(미용 동의서 6장, 3·4장 왼쪽 위 조판 숫자를 지운 판)와 `content/consent-guidelines.pdf`(교육미용 안내사항 1장)다. 서버가 이 위에 칸 값·체크·사인을 찍고 고른 장만 뽑아 기록 페이지를 붙인다. 한글은 `pretendard` 패키지의 Pretendard 글꼴을 PDF 안에만 넣는다.
- 칸 좌표·묶음은 `lib/consent-docs.ts` 에 있다. 보호자 화면의 장 그림(`public/consent-v1-<장>.png`)·화면 읽기용 글(`content/consent-text.ts`)·인쇄 글자 위치 표본(`tests/consent-words.json`)은 `scripts/consent-pages.mjs` 가 원본에서 만든다(poppler 의 `pdftoppm`·`pdftotext` 필요, `brew install poppler`).
- 원본 PDF 를 바꿀 때:
  1. 같은 이름으로 덮어쓴다. **칸 위치가 같아야 한다.** 칸이 움직였으면 `lib/consent-docs.ts` 의 좌표(`LAYOUT`)를 다시 잰다. 사장님이 InDesign 에서 다시 내보내면 3·4장 왼쪽 위의 숫자 글상자도 지워야 한다.
  2. `lib/consent-docs.ts` 의 그림 이름 `consent-v1-` 을 `consent-v2-` 로 올리고 `pnpm exec tsx scripts/consent-pages.mjs` 로 그림·글·표본을 다시 만든다. 옛 `v1` 그림은 지운다. 카카오톡·브라우저가 그림을 주소별로 저장해 같은 이름이면 옛 그림이 보인다.
  3. `pnpm test` 로 칸 좌표를 새 표본(`tests/consent-words.json`)과 견주는 테스트를 다시 돌리고, `pnpm exec tsx scripts/consent-sample.mjs` 의 표본 PDF 를 눈으로 본다. 스크립트는 원본 둘의 sha256 도 `content/consent-text.ts` 의 `CONSENT_SOURCE_SHA256` 에 적는다. 원본만 덮어쓰고 스크립트를 다시 돌리지 않으면 `pnpm test` 가 실패한다(장 그림·글·표본이 옛 원본 그대로 남지 않게).
  4. 서명 내용 고유값에는 원본 파일의 고유값이 들어간다. 옛 서명의 고유값을 다시 계산하려면 그때 원본이 필요하니 옛 파일을 따로 보관한다(저장소 기록에도 남는다). 원본을 바꾼 뒤에는 옛 서명의 메일을 다시 보낼 수 없다(다시 만든 PDF 의 고유값이 달라 '원본 문서나 시트 기록이 서명 때와 달라 다시 만들 수 없어요.' 가 뜬다). 메일이 실패한 동의서는 원본을 바꾸기 전에 다시 보낸다.

## 알려진 제약

- 이어 쓰기는 같은 기기·같은 브라우저에서만 된다(초안은 브라우저의 `localStorage` 에 있다). 다른 기기에서는 처음부터다. 저장소를 막은 브라우저에서는 같은 탭의 메모리에만 남아 새로 고치면 사라진다.
- 아이폰 사파리는 사파리를 쓴 날로 7일 동안 이 웹을 한 번도 쓰지 않으면 이 웹의 저장소(`localStorage`)를 지울 수 있다(WebKit 의 추적 방지 정책, 2020-03 발표). 그러면 쓰던 초안과 신청 세션이 사라져 처음부터 쓴다.
- 재시도하면 같은 신청 ID 의 줄이 시트에 두 번 생길 수 있다. 서버가 막지 않는다. 시트에서 `신청 ID` 로 찾아 한 줄을 지운다.
- 요청 빈도 제한이 없다. 스팸은 숨은 허니팟 칸과 글자 수 상한(짧은 답 200자, 긴 답 3,000자)으로만 거른다.
- 검사지를 두 창에서 거의 동시에 내면 두 줄이 쌓일 수 있다(이미 냈는지 보고 쓰는 사이가 막혀 있지 않다). 시트에서 한 줄을 지운다.
- 뒤로 가기 이력 처리의 받아들인 한계 셋:
  - 서버가 신청을 거절해(예: 화면이 열려 있는 사이 자정을 넘겨 희망 날짜가 과거가 됨) 오류가 있는 묶음으로 옮겨 간 직후에는 ‹ 를 한 번 눌러도 같은 묶음에 머물거나 한 묶음을 건너뛸 수 있다.
  - 새로 시작한 양식(신청서·검사지)에서 브라우저 앞으로 가기로 지난 초안의 칸에 닿으면 그 앞으로 가기는 먹지 않는다.
  - 검사지를 낸 뒤의 닫힌 안내에서 브라우저 앞으로 가기로 낸 검사지의 칸에 닿으면 그 앞으로 가기는 먹지 않는다.
- 검사지 머리말의 "*표시는 필수 질문임" 한 줄은 뺐다. 화면이 필수 문항에 `*` 를 붙이지 않고 선택 문항에 `선택` 을 붙이기 때문이다. 그 밖의 질문·선택지·안내는 오타까지 원문 그대로다.
- Vercel Hobby 약관은 비상업용이다(위 비용 절).
