# 교육미용 동의서 전자 서명 — 설계

2026-11-03. 기존 설계(`2026-10-23-hisshaus-form-design.md`, `2026-10-30-survey-link-design.md`)에 기능 하나를 더한다. 겹치는 규칙(제출 순서, 로그, 비밀값, 외부 스크립트 금지, basePath)은 `CLAUDE.md` 가 그대로 맞다.

## 1. 왜

사장님은 교육미용 손님에게 종이 동의서·계약서를 받아 왔다. 이걸 웹에서 보여 주고 손가락 사인을 받아 PDF 로 남기고 싶다. 사용자(개발 담당)는 "모두의싸인처럼 효력이 있는 방식"을 원했다.

- 효력: 2020년 개정 전자서명법상 화면에 손으로 그린 사인도 당사자가 그 방식을 고르면 서명으로서 효력이 있다. 모두의싸인이 다른 점은 다툼 때 낼 **증거 기록**(누가·언제·무엇에·바뀌지 않았음)이다. 그 기록을 이 웹이 남긴다.
- 돈: 유료 서비스(문자 인증·전자서명 서비스·파일 저장소)를 쓰지 않는다(사용자 결정). 완성 PDF 는 **메일로 보관**한다.

## 2. 목표 · 비목표 · 반목표

목표
- 보호자가 휴대폰(카톡으로 받은 링크) 또는 매장 아이패드에서 동의서를 읽고 사인한다.
- 사인이 들어간 PDF 가 사장님 보관 메일함과 보호자 메일함에 각각 한 통씩 간다. 보호자는 완료 화면에서도 바로 내려받는다.
- 증거 기록이 남는다: 완성 PDF 끝의 기록 페이지, 시트의 서명 기록(값·사인·PDF 고유값).
- 사장님이 적을 칸은 최소다. 보호자 정보는 신청서에서 미리 채운다.

비목표
- 문자 인증·휴대폰 본인인증(유료, 사용자 결정 "유료는 아직 쓰지 않을 거야").
- 공인 인증서로 PDF 를 봉인하는 일.
- 파일 저장소(구글 드라이브·S3 등). PDF 원본 보관은 메일함이 맡는다(사장님 "이렇게 해도 돼").
- 보호자 계정·로그인.
- 동의서 내용을 웹에서 고치는 기능. 문구가 바뀌면 PDF 파일을 바꿔 넣는다.
- 5년 지난 기록 자동 삭제(사장님이 메일·시트에서 지운다).
- 법률 검토(사용자에게 변호사·대한법률구조공단 검토를 권했다).

반목표(기술적으로 돌아가도 실패)
- 서명이 어디에도 남지 않고 사라지는 것(메일 실패 + 기록 없음).
- 보호자가 보지 않은 장에 사인이 찍히는 것. 고른 장 말고 다른 장이 PDF 에 섞이는 것.
- 사장님 화면이 비밀번호 없이 열리거나, 아이패드를 건네받은 보호자가 다른 손님 정보를 볼 수 있는 것.
- 서명 링크를 추측해 남의 동의서를 열 수 있는 것.
- 로그에 이름·연락처·메일 주소·사인·키가 남는 것.

## 3. 문서

원본은 사장님이 만든 PDF 두 개다(2026-11-03 받은 판). 저장소에 넣는다(위치는 빌더 몫, 아래 7절).

- `HISS_HAUS_미용 동의서.pdf` — 6장, 장마다 따로 사인하는 문서.
  1. 반려견 교육 서약서
  2. 행동수정 프로그램 계약서
  3. 신뢰쌓기 프로그램 계약서
  4. 그루밍 트레이닝 프로그램 계약서
  5. 교육을 마치지 않은 상태의 반려견의 미용 동의서(사장님 말로 "교육 중단 동의서")
  6. 교육을 하지 않은 상태의 반려견의 미용 동의서(사장님 말로 "교육을 받지 않는 일반 미용")
- `HISS_HAUS_교육미용안내사항.pdf` — 1장, 사인 칸 없음. 아래에서 "안내사항".

알려진 문서 문제: 3장 '환불' 칸의 "정책 2-c 기준에 한하여 보강 수업 가능합니다" — 문서 안에 2-c 가 없다. 사장님께 묻는 중이다. 3·4장 왼쪽 위 모서리에 찍혀 있던 조판 흔적 "3", "4" 글자는 배경 레이어(Form XObject)에서 그 글자 블록만 빼서 지웠다(2026-11-03, `HISS_HAUS_미용 동의서_숫자삭제.pdf`. 원본과 그려 비교해 그 자리 말고 바뀐 픽셀이 없음을 확인). 이 파일을 원본으로 쓴다. 사장님이 InDesign 에서 다시 내보낼 때는 그 글상자도 지워야 한다. 고친 PDF 가 와도 **칸 위치가 같으면** 파일만 바꿔 넣는다(칸 위치가 바뀌면 좌표를 다시 잡는다).

### 3.1 묶음 (사장님 결정 2026-11-03)

사장님이 아래 다섯 중 하나를 고르면 그 장들이 이 순서로 간다.

| 고르는 것 | 보내는 장(순서대로) | 사장님이 채울 칸 |
|---|---|---|
| 행동수정 트레이닝 | 1 서약서, 2 행동수정 계약서, 안내사항 | 프로그램 명, 수업 목표 |
| 신뢰쌓기 | 1, 3 신뢰쌓기 계약서, 안내사항 | 수업 시간 |
| 그루밍 트레이닝 | 1, 4 그루밍 트레이닝 계약서, 안내사항 | 없음 |
| 교육 중단 미용 동의서 | 5 | 금일 진행하는 미용(부위 체크) |
| 일반 미용 | 6 | 금일 진행하는 미용(부위 체크) |

사장님이 쓴 순서("1,2,*")를 그대로 따른다(안내사항이 끝). 5·6 은 미용하는 날마다 새로 만든다(부위가 그날 아이 상태로 정해진다).

**6 은 일반 미용 손님 모두에게 미용할 때마다 받는다**(사장님 결정 2026-11-03). 그래서 서명 건수는 미용 건수만큼이다. 이 때문에:
- 6 묶음은 한 장 + 기록 페이지라 PDF 를 작게(목표 300KB 안팎) 만든다. 보관 메일함이 5년을 버티게 하려는 것이다.
- 시트의 서명 기록도 줄마다 가볍게(사인 데이터는 몇 천 자 안쪽) 둔다. 5년이면 수천 줄이 된다.
- 메일함이 가득 차거나 메일이 사라져도 시트 기록으로 PDF 를 다시 만들 수 있다(4.5). 그래서 시트 기록이 마지막 보루다.
- 미용마다 슬랙 알림 한 통·보호자 메일 한 통이 간다(내 판단 — 슬랙은 채널 알림을 끄면 되고, 보호자 사본은 증거다).

### 3.2 칸과 채우는 사람

| 칸 | 있는 장 | 채우는 것 |
|---|---|---|
| 의뢰인·반려견 정보: 성함, 연락처(`010 - -` 꼴), 반려견 이름, 견종 | 2~6 | 신청서 값으로 미리 채우고 보호자가 확인·수정(4절). 신청서가 없으면 보호자가 직접 적는다 |
| 작성일(`20 년 월 일`) | 1~6 | 서명한 날(한국 시각) |
| 교육 담당자 | 1~6 | "히스하우스"(1·4장은 이미 인쇄돼 있다. 나머지 장도 같은 값, 내 판단) |
| 보호자 성함 | 1~6 | 확인한 성함 |
| 보호자 서명 | 1~6 | 보호자가 그린 사인 |
| 프로그램 명, 수업 목표 | 2 | 사장님이 적는다(자유 글) |
| 수업 시간 | 3 | 사장님이 적는다(자유 글) |
| 금일 진행하는 미용 15칸(등·배·앞다리·뒷다리·발톱깎기·발바닥털정리·항문낭압출·귀청소·목욕&드라이·얼굴컷트·눈앞컷트·귀바깥털·발등·생식기털·항문털) | 5·6 | 사장님이 체크한다. 체크한 칸에 표시를 찍는다 |

칸 이름은 PDF 원문 그대로다.

## 4. 흐름

### 4.1 사장님: 동의서 만들기
1. 사장님 화면에 비밀번호로 들어간다.
2. 신청 목록(예약신청 탭)에서 이름·연락처로 찾아 고르거나, **신청서 없이 새로 만들기**(전화 예약·매장 방문 손님)를 누른다.
3. 묶음 다섯 중 하나를 고르고, 그 묶음에 해당하는 칸만 채운다(3.2).
4. 둘 중 하나:
   - **링크 복사** → 카톡으로 보호자에게 보낸다.
   - **이 기기에서 바로 서명** → 아이패드를 보호자에게 건넨다. 사장님 로그인은 유지한 채 그 기기를 **잠근다**. 잠긴 동안에는 서명 화면만 열리고, 뒤로 가기·주소창으로 사장님 화면에 가도 **4자리 PIN** 화면만 보인다. 서명이 끝나면 "기기를 사장님께 돌려주세요" 화면에서 멈춘다. 사장님이 PIN 을 넣으면 풀린다. PIN 을 5번 틀리면 그 기기의 로그인이 풀려 전체 비밀번호를 다시 물어야 한다(사용자 결정 2026-11-03 — 미용마다 매장에서 사인받으니 긴 비밀번호를 매번 넣지 않게. 처음 설계는 건넬 때 로그아웃이었다).

### 4.2 보호자: 서명
1. **정보 확인**: "계약서에 이렇게 들어가요. 틀린 곳이 있으면 고쳐 주세요." 성함·연락처·반려견 이름·견종이 신청서 값으로 채워져 있고 고칠 수 있다. 그리고 **사본을 받을 이메일**을 적는다(필수). 신청서 없이 만든 동의서는 칸이 비어 있다.
2. **문서 읽기**: 고른 장을 순서대로 보여 준다. 장마다 "읽고 동의해요"(안내사항은 "확인했어요")를 체크해야 다음으로 간다. 사장님이 채운 칸과 보호자 정보가 들어간 모습으로 보여 준다.
3. **서명**: 사인 칸에 한 번 그린다(다시 그리기 가능). 이 사인이 고른 모든 장의 서명 칸에 들어간다(내 판단 — 장마다 동의 체크를 따로 받으므로). "전자 방식으로 서명하는 데 동의해요"를 체크한다. 이메일을 한 번 더 보여 준다("이 주소로 사본을 보내요").
4. **제출** → 완료 화면: "서명이 끝났어요", PDF 내려받기 버튼, "메일로 사본을 보냈어요"(메일이 실패했으면 "사본 메일은 곧 다시 보내 드릴게요").
5. 링크는 닫힌다. 다시 열면 "이미 서명한 동의서예요" 안내(검사지 닫힘과 같은 꼴).

화면 맨 아래에 작은 회색 글씨로 **"ⓒ 어글리독 All rights reserved"**(사용자 결정 2026-11-01). 화면 문구는 해요체다. 동의서 본문(PDF)은 사장님 문서 그대로다.

### 4.3 서버: 제출 처리
순서는 **검증 → 시트 → 메일 → 슬랙**이다(기존 규칙에 메일이 끼어든다).
- 검증: 링크가 맞고 아직 서명되지 않았는지(시트 확인), 필수 칸, 체크, 사인이 있는지.
- 시트: '동의서' 탭에 서명 한 줄. 실패하면 실패로 답한다(보호자가 다시 누른다).
- PDF 를 만들고 고유값(SHA-256)을 구한다. 시트 줄에 고유값을 함께 적는다(시트 쓰기 전에 PDF 를 만든다).
- 메일: 보관용(`MAIL_ADDRESS` 자신에게) 한 통, 보호자에게 한 통. 실패해도 기록이 남았으므로 성공으로 답한다.
- 슬랙: "동의서 서명" 알림(아래 4.4). 실패해도 성공.
- 같은 링크를 두 번 내면(응답을 못 받은 재시도) 시트에서 이미 서명됐는지 보고 쓰지도 보내지도 않고 성공으로 답한다(검사지와 같다).

### 4.4 슬랙 알림
- 첫 줄: 동의서 서명 · 보호자 성함 · 반려견 이름 · 묶음 이름.
- **신청서와 달라진 값**이 있으면 "견종 말티 → 말티즈" 꼴로 모두(사용자 결정 — 보호자가 고친 것을 사장님이 알게).
- 메일 결과: 보관용·보호자 사본 각각 보냄/실패.
- 신청 ID(있으면)와 동의서 ID.

### 4.5 메일이 실패했을 때
시트 줄에는 PDF 를 다시 만들 수 있는 값이 모두 있다(칸 값·사인·묶음·서명 시각). 사장님 화면의 동의서 목록에서 **메일 다시 보내기**를 누르면 같은 내용으로 PDF 를 다시 만들어 보관용·보호자에게 보낸다(내 판단). 다시 만든 PDF 가 바이트까지 같을 필요는 없지만, 같게 만들 수 있으면(PDF 메타데이터의 날짜를 서명 시각으로 고정 등) 고유값이 그대로라 더 좋다(빌더 몫).

## 5. 증거 기록

완성 PDF 맨 끝에 **기록 페이지** 한 장을 붙인다.
- 문서 묶음 이름과 들어간 장 목록
- 보호자 성함·연락처·이메일, 반려견 이름
- 서명 시각(한국 시각, 초까지)
- 서명한 기기(브라우저 User-Agent 를 그대로 또는 읽기 쉽게)
- 동의서 ID, 신청 ID(있으면)
- 보호자가 체크한 동의 문구들("전자 방식으로 서명하는 데 동의해요", 장마다 "읽고 동의해요")
- 신청서와 달라진 값(있으면)
- **서명 내용 고유값**(SHA-256) — 원본 문서 두 파일의 고유값과 묶음·장 목록·칸 값·사인·서명 시각·동의서 ID·신청 ID·기기·동의 문구·고친 값을 정해진 키 순서의 JSON(v1)으로 묶은 글의 고유값(`lib/consent-pdf.ts` 의 `consentContentHash`). PDF 바이트·라이브러리 판과 무관해서 시트의 서명 기록과 원본 문서로 다시 계산할 수 있다. 기록 페이지가 자기 고유값을 담을 수는 없으므로 시트에는 이 값과 **완성 PDF 전체**의 고유값을 따로 적는다(처음엔 "기록 페이지 앞 장들" 의 PDF 고유값이었는데, 최종 파일에서 다시 구할 수 없어 바꿨다 — 통제자 결정 R6, 2026-11-03)
- 맨 아래 "ⓒ 어글리독 All rights reserved"

IP 주소는 남기지 않는다(내 판단 — 개인정보를 덜 받는다. 링크·연락처·시각·기기·고유값으로 충분하다고 봤다).

## 7. 빌더에게 맡기는 것 (제약과 함께)

- **사장님 비밀번호와 PIN**: 새 환경 변수 둘(비밀번호, 4자리 PIN. 이름은 빌더가 정하고 사용자에게 알린다. 사용자가 Vercel 에 직접 넣는다). 잠금 상태와 틀린 횟수는 서버가 확인할 수 있게 둔다(예: 서명된 쿠키 — 쿠키를 지우면 로그인도 풀리므로 횟수를 되돌릴 수 없다). 사장님 화면·API 는 잠긴 동안 PIN 화면 말고는 아무것도 주지 않는다. 비교는 시간 차가 드러나지 않게, 틀리면 짧게 기다리게. 로그인 상태는 서명된 HttpOnly 쿠키. 사장님 화면·API 는 `no-store`, `noindex`.
- **링크 서명**: 검사지 링크(`lib/survey-link.ts`)와 같은 방식으로 하되, 검사지 링크로 동의서가 열리거나 그 반대가 되지 않게 용도를 나눈다. `SURVEY_LINK_SECRET` 을 용도 구분과 함께 다시 써도 되고 새 변수를 만들어도 된다(새 변수면 사용자에게 알린다).
- **사장님이 채운 칸을 어디에 두나**: 링크를 만들 때 시트에 '준비' 기록을 남기거나, 서명된 토큰에 담는다. 링크가 카톡에서 지나치게 길어지지 않게. 링크 취소와 "이미 서명함" 확인이 되어야 한다.
- **시트**: '동의서' 탭(이름은 빌더가 정해 README 에 적는다). 열은 정의 한 곳에서 만들고 `pnpm sheet:header` 가 이 탭 헤더도 찍게 한다. 셀 하나는 5만 자까지라 사인 그림은 그 안에 들어가게 줄이거나(작은 PNG, 선 좌표 등) 나눠 담는다. `valueInputOption=RAW` 그대로.
- **PDF 만들기**: 서버(Node 런타임)에서 원본 PDF 위에 글자·체크·사인을 찍고 고른 장만 뽑아 기록 페이지를 붙인다(예: `pdf-lib`). 한글을 찍으려면 한글 글꼴 파일을 저장소에 넣어 PDF 안에 넣는다(브라우저가 외부에서 받는 글꼴이 아니므로 "외부 글꼴 금지" 규칙과 부딪히지 않지만 `CLAUDE.md` 에 한 줄 적는다). 글꼴은 무료 배포 가능한 것(OFL 등), 필요한 글자만 넣어 크기를 줄인다. 칸 좌표는 빌더가 원본에서 잰다.
- **화면에 문서 보여 주기**: 휴대폰에서 읽을 수 있게(확대 가능). 원본을 그림으로 바꿔 두든, 서버가 칸을 채운 미리보기 그림을 만들든 빌더 몫. 화면 읽기 프로그램을 위해 문서 글자도 읽을 수 있게 한다.
- **사인 칸**: 포인터 이벤트로 그린다. 외부 스크립트는 안 되고, npm 패키지를 번들에 넣는 것은 된다.
- **메일**: `nodemailer` 등. 제목·본문 글은 해요체. 첨부 파일 이름에 보호자·반려견 이름과 날짜. 네이버 SMTP 로 보낸 메일이 보낸메일함에도 남는지 확인해 `docs/OPERATIONS.md`(옛 README 비용 표) 에 적는다(남으면 한 건이 메일함에 세 벌 쌓여 용량 계산이 달라진다).
- **e2e**: 진짜 메일·시트·슬랙을 부르지 않는다. 가짜 SMTP 를 기존 가짜 서비스처럼 테스트 전용 변수로 붙인다(운영에서는 읽지 않는다). 휴대폰 폭과 아이패드 폭에서 서명 흐름, 사장님 로그인·묶음별 칸, 이미 서명한 링크, 메일 실패 시 성공 답과 슬랙 표시를 본다.
- **개인정보 안내**: 서명 화면 첫 단계에 수집 항목(이메일·사인·서명 기기 정보·서명 시각)과 보관 기간(5년)을 적는다. 초안은 빌더가 쓰고 사장님 확인을 받는다.
- **로그 규칙 추가**: 지금 로그는 "시트 저장 실패"·"슬랙 전송 실패"와 신청 ID 만이다. "메일 전송 실패" + 동의서 ID 를 더하고 `CLAUDE.md` 를 고친다. 그 밖의 값(주소·사인·오류 객체)은 찍지 않는다.
- **README**: 비용 표에 네이버 메일(무료, 하루 발송 한도는 공개 숫자를 못 찾았다, 매장 규모로는 닿지 않는다. **메일함 용량이 유료로 바뀌는 지점**이다 — 한 건 크기 × 미용 건수로 몇 년 버티는지 적고, 용량이 차기 전에 사장님이 할 일(오래된 메일 PC 로 내려받아 지우기 등)을 적는다), 변수 표에 메일 둘·사장님 비밀번호, 시트 탭 만들기, 사장님 사용법(링크 만들기·아이패드 서명·메일 다시 보내기).

## 8. 성공 기준

- 다섯 묶음 각각, 고른 장만 그 순서로 PDF 에 들어가고 모든 칸·체크·사인이 제자리에 찍힌다(사장님이 종이에 손으로 쓴 것과 견줘 어색하지 않은 위치).
- 휴대폰(카톡 브라우저 포함)과 아이패드에서 링크 열기 → 정보 확인 → 장마다 동의 → 사인 → 완료까지 막힘이 없다.
- 서명 한 건마다 시트 한 줄, 보관 메일 한 통, 보호자 메일 한 통, 슬랙 한 통. 같은 링크를 두 번 내도 한 번뿐이다.
- 메일이 실패해도 보호자는 성공 화면과 PDF 내려받기를 보고, 사장님은 슬랙에서 실패를 알고 사장님 화면에서 다시 보낼 수 있다.
- 서명한 링크는 다시 서명할 수 없다. 틀린 링크는 아무 동의서도 보여 주지 않는다.
- 사장님 화면은 비밀번호 없이 열리지 않는다. 아이패드 서명 중·뒤에는 PIN 없이 사장님 화면이 보이지 않고, PIN 을 5번 틀리면 비밀번호부터 다시다.
- 로그에 개인정보·키가 없다. 단위 테스트·형 검사·빌드·e2e 가 모두 통과한다.
