# 검사지를 링크 받은 사람만 — 설계

2026-10-30. 기존 설계(`2026-10-23-hisshaus-form-design.md`)의 검사지 진입·제출 부분을 바꾼다. 거기와 다르면 이 문서가 맞다.

## 1. 왜

사장님(2026-10-30): "심층상담지는 교육미용 상담할 때 금액을 받고 하는 거라, 일반 사람이 그거를 볼 수 있게 만들면 안 돼."

지금은 검사지에 세 길로 들어올 수 있다. 첫 화면의 검사지 카드, 교육미용을 고른 신청 직후의 검사지 안내(입금 전), `/hisshaus/survey` 주소를 직접 여는 것. 셋 다 누구나 98문항을 볼 수 있다.

흐름(사장님 확인): **신청서 → 사장님이 연락 → 예약금(50,000원) 입금 확인 → 사장님이 카톡으로 검사지 링크를 보냄 → 보호자가 그 링크로 검사지를 씀.**

## 2. 목표 · 비목표 · 반목표

목표
- 보호자에게 보이는 것은 예약 신청서뿐이다. 검사지는 사장님이 보낸 링크로만 열린다.
- 링크는 시간이 지나도, 몇 번을 열고 닫아도 만료되지 않는다(검사지가 길어서 나눠 쓴다). 쓰던 자리는 지금처럼 그 기기에 남는다.
- 링크는 추측·위조할 수 없다. 링크가 틀리면 문항 글자를 아예 보내지 않는다(숨기는 것이 아니라 내려가지 않는다).
- 제출하면 그 링크는 닫힌다. 제출 직전에 "제출하면 답을 고칠 수 없어요" 를 한 번 확인받는다.
- 검사지가 어느 신청 건인지 자동으로 이어진다.

비목표
- 로그인·문자 인증. 보호자가 제출 **전에** 링크를 남에게 넘기면 그 사람도 볼 수 있다. 받아들인 한계다(문자 인증은 건당 비용).
- 링크 만료·사장님이 링크를 끄는 기능.
- 다른 기기에서 이어 쓰기(초안은 지금처럼 그 브라우저에만 있다).

반목표
- 링크 없이 문항이 보이는 길이 하나라도 남는 것(HTML·JS 어디에든).
- 보호자가 쓰다가 링크가 갑자기 막히는 것(만료·세션 때문에).

## 3. 정한 것

| 무엇 | 결정 | 누가 |
|---|---|---|
| 흐름 | 신청 → 연락 → 입금 확인 → 카톡으로 링크 | 사장님 |
| 링크 | 신청마다 하나. 만료 없음 | 사용자 |
| 제출 뒤 | 링크가 닫힌다. 제출 전에 경고 한 번 | 사용자 |
| 첫 화면 | 예약 신청서만 | 사용자 |
| 주소 | 지금처럼 `chagocnote.com/hisshaus/...`. 주소의 앞부분은 상수 한 곳(`lib/base-path.ts` 의 `SITE_ORIGIN`)에 둬서 히스하우스 전용 도메인으로 옮길 때 한 줄만 고친다 | 사용자 질문에 대한 내 판단 |
| 경고 창 | 브라우저 기본 `confirm` 이 아니라 화면 안에 그린 창(카톡 브라우저의 기본 창은 주소가 찍힌다) | 내 판단 |
| 링크 만드는 명령 | `pnpm survey:link [신청ID]` — 배포 전에 들어온 교육미용 신청, 신청서 없이 카톡으로만 온 손님용. 신청 ID 를 안 주면 새로 만든다 | 내 판단(사용자에게 알림) |

## 4. 화면

### 4.1 첫 화면
- 검사지 카드를 지운다. 양식 카드는 예약 신청서 하나다.
- 머리 안내 "작성할 양식을 골라 주세요." → "신청서를 작성해 주세요."(고를 것이 하나라서, 내 판단).

### 4.2 신청서 완료
- 교육미용을 골라도 검사지 안내(`/apply/training`)를 거치지 않고 바로 완료 화면이다.
- 완료 화면의 '검사지 이어서 쓰기' 버튼을 지운다. 버튼은 늘 [카카오톡 채널로 문의하기] + [확인].
- 교육미용이면 다음 순서 끝에 한 줄: "5. 입금이 확인되면 카카오톡으로 검사지 링크를 보내 드려요".
- 지우는 것: `/apply/training` 화면(`TrainingIntro`), '교육미용은 아니에요' 버튼, `/api/apply/cancel-training`, 슬랙 취소 알림, 세션의 `surveyDone`.

### 4.3 검사지 주소
| 주소 | 보이는 것 |
|---|---|
| `/survey` | "검사지는 받은 링크로 열어 주세요" 안내. 본문: "심층 행동 분석 검사지는 교육미용 상담 예약금 입금이 확인된 뒤 카카오톡으로 링크를 보내 드려요." 버튼: [카카오톡 채널로 문의하기] [처음으로] |
| `/survey/<틀린 값>` | `/survey` 로 보낸다(redirect). 이 주소의 응답에는 검사지 화면 코드가 실리지 않는다 |
| `/survey/<맞는 링크>`, 아직 안 냄 | 검사지 |
| `/survey/<맞는 링크>`, 이미 냄 | "이미 제출된 검사지예요" 안내. 본문: "고칠 내용이 있으면 카카오톡 채널로 알려 주세요." 버튼: [카카오톡 채널로 문의하기] [처음으로] |
| `/survey/done` | 검사지 완료 |

- 이미 냈는지 시트를 못 읽으면(시트 장애) 검사지를 그대로 연다. 제출 때 다시 확인한다.
- 검사지 화면: 미리 채우기 없음(성함·연락처·반려견 이름도 검사지에서 적는다). 첫 묶음의 '이전' 은 막는다(링크로 들어와서 돌아갈 곳이 없다).
- 초안: 이 링크의 신청 ID 로 묶는다. 저장된 초안이 다른 신청 ID 거나 신청 ID 가 없으면(옛 흐름의 초안) 버리고 새로 시작한다. 새 초안의 신청 ID 는 링크의 신청 ID 다.
- 마지막 묶음의 '제출하기' → 화면 안 확인 창: "제출하면 답을 고칠 수 없어요. 제출할까요?" [다시 볼게요] [제출하기]. 다시 볼게요는 창만 닫는다. 신청서에는 이 창이 없다.

### 4.4 검사지 완료 화면
- 제목 "검사지가 잘 도착했어요". 본문 "상담 전에 꼼꼼히 읽어 볼게요. 고칠 내용이 있으면 카카오톡 채널로 알려 주세요."
- 예약금·계좌 안내와 '예약 신청서 쓰기' 안내를 지운다(이미 입금한 뒤다).
- 버튼 [카카오톡 채널로 문의하기] [처음으로](처음으로는 지금처럼 세션과 초안을 지운다). 출처 한 줄은 그대로.
- 이 화면은 문항 정의(`forms/survey.ts`)를 불러오지 않는다. 출처 글은 따로 둔 상수를 읽는다(누구나 열 수 있는 주소라서, 불러오면 문항 전체가 그 화면의 JS 에 실린다).

## 5. 링크

- 모양: `{SITE_ORIGIN}{BASE_PATH}/survey/{신청ID}-{서명}`. 예: `https://chagocnote.com/hisshaus/survey/Ab3dE5gH7j-3f9a…`.
- 서명: `HMAC-SHA256(비밀값, "survey:" + 신청ID)` 를 16진수로 적은 앞 32자(128비트). 영숫자만 써서 링크가 `-`·`_` 로 끝나지 않는다(카톡·슬랙이 링크 끝의 기호를 떼어 낼 수 있다, 최종 리뷰 2026-10-30). 확인은 같은 값을 다시 만들어 시간 일정 비교(`timingSafeEqual`).
- 비밀값: 환경 변수 `SURVEY_LINK_SECRET`, 필수, 32자 이상(짧으면 이름만 담은 오류). 만들기: `openssl rand -base64 32`. 바꾸면 이미 보낸 링크가 모두 막힌다.
- 링크는 서버에서만 만들고 확인한다(`lib/survey-link.ts`). 브라우저로 가는 값은 링크 그 자체뿐이다.

## 6. 서버

### 6.1 신청서 제출
- 교육미용이 든 신청이면 슬랙 메시지 끝(신청 ID 줄 바로 앞)에 한 단락: "📋 *검사지 링크* — 입금 확인 뒤 보내 주세요" + 줄바꿈 + 링크. 메시지가 여러 통으로 나뉘면 마지막 통에 붙는다.
- 시트에는 링크를 적지 않는다(열이 바뀌지 않는다).

### 6.2 검사지 제출 `/api/survey`
- 본문: `{ token, answers, website }`. `submissionId`·`applyId` 는 받지 않는다.
- 순서: 허니팟 → 링크 확인(틀리면 400) → 답 모양 → 숨은 문항·빈 답 버리기 → 검증 → **시트**(검사지 탭 ID 열에 이 신청 ID 가 있나 → 있으면 쓰지도 슬랙도 보내지 않고 성공으로 답한다 → 없으면 한 줄 붙임) → 슬랙.
  - 이미 냈는데 또 온 것은 대개 응답을 못 받은 재시도다. 성공으로 답하면 보호자는 완료 화면을 본다.
  - 시트 읽기·쓰기 실패는 하나로 본다: 로그 `시트 저장 실패` + 신청 ID, 503.
  - 두 창에서 거의 동시에 내면 두 줄이 될 수 있다. 받아들인다.
- 검사지 행의 신청 ID 칸은 링크의 신청 ID 다(예약신청 탭과 같은 ID). 슬랙 첫 통에는 늘 "예약 신청 {ID}의 검사지예요".

### 6.3 시트 읽기
- `lib/sheets.ts` 에 검사지 탭 B열(신청 ID)을 읽는 함수. `GET /v4/spreadsheets/{id}/values/'검사지'!B:B`. 실패는 `Error('sheets')` 만 던진다(appendRow 와 같은 규칙). 권한 범위는 지금(`spreadsheets`) 그대로.
- 링크를 열 때 한 번, 제출할 때 한 번 읽는다. Sheets API 읽기 한도(프로젝트당 분당 300건) 안이라 무료다. README 비용 표에 적는다.

### 6.4 헤더
- `/survey` 아래 전부에 `X-Robots-Tag: noindex, nofollow` 와 `Referrer-Policy: no-referrer` 를 더한다(링크가 검색에 잡히거나, 다른 사이트로 넘어갈 때 주소가 따라가지 않게). 기존 설계 6.4 의 "noindex 를 달지 않는다" 는 검사지 경로에서는 뒤집힌다.
- 링크 미리보기(og) 제목·설명·그림은 맞는 링크 화면에 그대로 둔다(사장님이 카톡으로 보낼 때 보인다).

## 7. 검증
- 단위: 링크 만들기·확인(틀린 서명·다른 ID·모양 깨짐·짧은 비밀값), 시트 읽기, 제출 순서(이미 냄·링크 틀림·읽기 실패), 슬랙 링크 단락(교육미용일 때만), 확인 창, 화면 문구 해요체.
- e2e:
  - 교육미용 신청 → 슬랙에서 링크를 꺼내 연다 → 확인 창 → 제출 → 완료 → 같은 링크를 다시 열면 '이미 제출된 검사지예요'.
  - 링크 없이·틀린 링크로 열면 안내만 보이고, 그 화면과 첫 화면·신청서·검사지 완료 화면이 불러온 HTML·JS 어디에도 검사지 문항 글이 없다.
  - 기존 검사지 e2e(이어 쓰기·공격성 분기·동의 막힘·폭 320·미리보기)는 링크로 연다.
- 가짜 시트(`tests/e2e/fake-services.mjs`)에 값 읽기(GET)를 더한다.
- 빌드 뒤 `.next` 에서 문항 글이 든 JS 조각이 검사지 화면 말고 다른 화면에 걸리지 않는지 한 번 본다.
