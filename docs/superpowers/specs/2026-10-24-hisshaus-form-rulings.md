# 히스하우스 신청서 웹 — 실행 중 판정 기록

2026-10-23~24, 계획(`docs/superpowers/plans/2026-10-23-hisshaus-form.md`)을 서브에이전트로 실행하면서 사용자 대신 내린 결정이다. 설계 문서가 답하지 않은 것, 계획이 틀렸던 것, 검토가 드러낸 빈틈을 이렇게 정했다. 각 줄은 "판정 — 이유 — 틀렸을 때 드는 비용" 순서다. 틀린 것이 있으면 이 문서를 근거로 되돌리면 된다.

## 문항

1. **신청서 14문항은 전부 필수, 라벨은 구글폼 원문.** 구현자가 성별·중성화·접종을 선택으로 두고 라벨을 지어냈던 것을 고쳤다 — 시트 헤더가 지금 구글폼 응답 시트와 같아야 사장님이 보던 대로 본다 — 틀리면 헤더 이름만 다르다.
2. **검사지 Q84·Q85는 선택 문항.** 구글폼 원본 데이터를 직접 뽑아 보니 원래 선택이었다(처음 옮긴 문항 문서가 틀렸다). 그래서 Q83 "없음" 특례도 없앴다 — 원문 그대로 — 틀리면 공격 대상 답을 못 받는 경우가 생기는데, 원본 폼도 같다.
3. **검사지 Q2(의뢰인 동의)는 필수·단일 선택, "동의하지 않음"이면 진행을 막는다.** 원본은 필수 표시가 없고 체크박스다 — 동의 없이 개인정보를 받지 않는다 — 틀려도 동의를 강제하는 쪽이 안전하다.
4. **검사지 Q21은 복수 선택.** 원본은 단일 선택이지만 안내문이 "a에서 1개, b에서 1개"를 고르라고 한다 — 사장님 의도 — 틀리면 시트 칸에 값이 둘 들어간다.
5. **검사지 머리말의 "*표시는 필수 질문임" 한 줄을 뺐다.** 이 화면은 필수에 `*` 를 붙이지 않고 선택 문항에 `선택` 을 붙인다. 질문 문장이 아니라 구글폼 화면 안내다 — 없는 표시를 가리키지 않게 — 틀리면 한 줄을 되돌린다.
6. **2순위 시간대는 2순위 날짜를 고르면 필수.** 처음엔 검증 코드의 특례였는데 화면의 `선택` 표시와 어긋나서 문항 정의(`requiredIf`)로 옮겼다 — 표시와 검증이 한 곳에서 정해지게 — 틀려도 형 필드 하나다.
7. **시간대 라벨을 `1순위 시간대`·`2순위 시간대` 로 나눴다.** 시트 헤더에 같은 이름이 두 칸이었다 — 시트를 만들기 전에 — 틀리면 라벨 두 개만 다르다.

## 서버·저장

8. **시트의 날짜는 `YYYY-MM-DD` 원문, 화면·슬랙은 `10월 28일 (수)`.** — 시트에서 정렬·필터가 되게 — 틀리면 시트의 날짜가 덜 읽기 좋다.
9. **로그는 "시트 저장 실패"/"슬랙 전송 실패" + 신청 ID 두 꼴만.** 오류 객체도 찍지 않는다 — fetch 오류 안에 웹훅 주소가 들어갈 수 있다 — 틀려도 운영 로그가 덜 자세할 뿐이다.
10. **시간 제한: 슬랙 한 통 5초, 시트 10초, 구글 토큰 한 시도 5초(응답 없음은 재시도 안 함, 5xx 는 라이브러리 재시도).** 라이브러리가 시간 초과를 두 번 더 재시도해 토큰만 최악 30초였다 — 함수 한도 30초 안에 들어오게 — 틀리면 구글이 잠깐 느릴 때 실패가 조금 잦다.
11. **시트는 `valueInputOption=RAW`.** — 보호자가 `=IMPORTXML(...)` 같은 걸 적어도 수식이 아니라 글자로 저장된다 — 바꾸면 수식 주입이 된다.
12. **교육미용 취소 알림이 실패하면 서버는 실패를 돌려주고, 화면은 무시하고 넘어간다.** — 취소 기록은 시트에 없다 — 틀리면 사장님이 취소를 모를 수 있다.
13. **화면이 숨긴 조건부 문항의 답은 서버가 조용히 버린다.** 공백뿐인 선택 답도 버린다(시트 '', 슬랙 '—'). 복수 선택의 중복·개수 초과는 거부한다 — 숨은 칸으로 4만 자를 밀어 넣으면 검증을 건너뛰고 슬랙 수십 통이 갔다 — 틀리면 화면이 숨긴 옛 답이 사라질 뿐이다(원래 의도).
14. **세 API 경로의 응답 처리를 `lib/http.ts` 하나로.** 계획은 파일마다 쓰라고 했다 — 같은 블록 세 번 중복 — 틀려도 파일 하나 더다.
15. **답 모양 검사를 `lib/guards.ts` 하나로 모았다(초안 복원과 서버 수락이 같이 쓴다).** — 두 규칙이 어긋나면 안 된다 — 틀려도 파일 하나 더다.
16. **테스트 전용 변수 `SHEETS_BASE_URL`·`SHEETS_FAKE_TOKEN` 은 운영(`NODE_ENV=production`)에서 무시한다.** — 운영 환경 변수에 잘못 남아도 보호자 정보가 다른 주소로 가지 않게 — 그래서 운영 빌드로는 e2e 를 못 돌린다.
17. **`pnpm-workspace.yaml` 에 `packages: ['.']`.** 없으면 pnpm 9 설치가 실패한다(Vercel 이 pnpm 9 를 고를 수 있다) — 첫 배포가 막히지 않게 — 틀려도 설정 두 줄이다.

## 화면·흐름

18. **검사지의 신청 ID 는 같은 브라우저의 신청 세션 ID 를 그대로 쓴다.** — 시트 두 탭이 같은 신청 ID 로 이어진다 — 틀리면 사장님이 이름으로 맞춰야 한다.
19. **신청서를 열 때 지난 신청 세션을 지우지 않는다. 다음 제출이 덮어쓴다.** 계획은 지우라고 했다 — 완료 화면에서 뒤로 가기만 해도 세션이 지워져 앞으로 가기 때 완료 화면이 첫 화면으로 튕겼다 — 틀리면 지난 신청 정보가 다음 제출 전까지 기기에 더 남는다.
20. **검사지 초안은 "다른 신청에 묶였던 것"만 버린다.** 세션 없이(링크로) 쓰기 시작한 초안은 나중에 신청을 내도 지키고 이어 쓴다 — 98문항을 쓰다 잃지 않게 — 틀리면 지난 신청의 검사지가 새 신청과 이어질 수 있다.
21. **오늘 날짜는 브라우저에서 화면을 연 뒤 계산한다. 제출 뒤 이동은 `router.replace`. 제출 요청은 35초 제한. 첫 화면 사진은 평범한 `<img>`. `metadataBase` 는 두지 않는다.** — 빌드 날짜가 굳지 않게, 보낸 화면으로 뒤로 한 번에 돌아오지 않게, 이미지 최적화 사용량을 쓰지 않게 — 틀리면 첫 화면 사진이 원본 크기 그대로 간다.
22. **저장소가 막힌 브라우저에서는 같은 탭 메모리에 대신 둔다.** — 제출이 성공했는데 완료 화면이 튕겨 다시 제출하는 일을 막는다 — 틀려도 메모리 몇 줄이다.
23. **이미 교육미용을 취소했거나 검사지를 낸 세션이면 검사지 안내 화면은 완료 화면으로 보낸다.** — 취소 알림 중복을 막는다.
24. **선택 문항의 단일 선택 칩은 다시 누르면 해제된다. 필수 문항은 해제되지 않는다.** 처음엔 늘 해제 안 함이었다 — 선택 문항에서 되돌릴 길이 없었다 — 틀리면 칩을 실수로 풀 수 있다.
25. **제출이 접수된 뒤의 입력은 초안으로 다시 저장하지 않는다.** — 다음 신청이 재시도 중복처럼 보이지 않게.

## 뒤로 가기(방문 기록)

26. **방문 기록 칸마다 양식·초안 열쇠·묶음·위치를 적는다(`hhForm`·`hhKey`·`hhStep`·`hhPos`).** 처음엔 "한 칸 = 한 걸음"으로 셌는데 새로 고침·여러 칸 건너뛰기에서 셈이 틀어져 ‹ 가 양식을 떠났다 — 칸이 스스로 위치를 말하게 — 틀리면 칸 state 에 필드 몇 개가 더 붙을 뿐이다.
27. **열쇠는 신청 ID 가 아니라 초안마다 새로 만든다. 지난 초안의 칸에 닿으면 건너뛴다.** 검사지를 낸 뒤 뒤로 오면 빈 검사지가 지난 칸 열 개를 거꾸로 밟았다 — 첫 묶음에서의 뒤로 가기는 "양식 떠나기"다 — 틀리면 앞으로 가기가 지난 칸에서 먹지 않는다.
28. **받아들인 한계: 탭의 맨 첫 칸이 지난 초안의 칸이면 ‹ 가 먹지 않는다.** 링크로 바로 연 검사지를 낸 뒤 탭의 처음까지 뒤로 가서 새 검사지를 이어 쓰는 경우다. 새로 고침하면 풀린다 — 드물어서 타이머 보강을 하지 않았다.

## 접근성·표시

29. **흐린 글자색을 흰 바탕 대비 4.5:1 위로(`#6e6e73`), 필수 입력에 `aria-required`.** 복수 선택 묶음(`role="group"`)에는 ARIA 규격상 달 수 없어 뺐다 — 화면 낭독기 사용자는 복수 선택 문항의 필수 여부를 미리 듣지 못한다(넘어가려 하면 오류 문구로 듣는다).
30. **연락처는 숫자·공백·하이픈·괄호와 맨 앞 `+` 를 받는다. 완료 화면은 `+82` 를 국내 꼴로 바꿔 가린다.** — 자동 채움이 국가 번호 꼴로 넣어도 고치지 않아도 되게 — `+82 010-…`(0을 한 번 더 쓴 꼴)·해외 번호는 완료 화면에서만 어색하게 가려진다(시트·슬랙은 원문).

## 도구·과정

31. **세션 중 모델이 바뀌어 커밋 끝 줄이 Fable 5.1 → Opus 5.5 로 바뀌었다.** 앞선 커밋은 고치지 않았다 — 이력 재작성 안 함 — 커밋 메시지 한 줄 차이다.
32. **e2e 는 전용 포트 3030·3031, 이미 떠 있는 서버를 쓰지 않는다, 다섯 환경 변수를 모두 넘긴다.** — 진짜 설정을 읽은 개발 서버를 재사용해 테스트 제출이 진짜 슬랙·시트로 가는 일을 막는다. Next 16 은 같은 폴더에 개발 서버 둘을 못 띄우므로 e2e 전에 `pnpm dev` 를 끈다.

## 미룬 것 (고치지 않았다)

- 운영 빌드(`next start`) 위에서 도는 브라우저 테스트가 없다. 지금 e2e 는 `next dev` 에서만 돈다.
- 슬랙 전송을 응답 뒤(`after()`)로 옮기지 않았다. 검사지가 모든 칸 최대 길이면 슬랙 12–13통이라, 슬랙이 느리면 30초를 넘겨 보호자가 실패를 보고 다시 보낼 수 있다(시트에 같은 신청 ID 의 줄이 둘).
- 화면 낭독기: 복수 선택 묶음과 "기타 내용" 입력의 필수 표시, 단일 선택 칩의 화살표 키 이동, 긴 묶음에서 오류 알림이 한꺼번에 많이 읽힘, 기타 입력 이름이 모두 "기타 내용".
- 다른 탭이 그 사이 새 신청 세션을 저장했으면 검사지·검사지 안내가 마운트 때 읽은 옛 세션으로 덮어쓴다(드묾).
- 브라우저 앞으로 가기는 검증 없이 다음 묶음으로 간다(서버 검증과 재검사가 그물).
- 빈도 제한이 없고, 교육미용 취소 경로에는 허니팟이 없다(설계가 빈도 제한을 뺐다). 세션은 만료되지 않는다(공용 기기에서 이전 보호자 이름이 미리 채워질 수 있다).
- 테스트 정리: e2e 의 중복 선택자·도우미 사용 불일치, 시트 행 테스트의 조건부 단언, 슬랙 블록 50개 분할 경로를 직접 덮는 테스트, 설정 모듈의 서비스 계정 JSON 깨짐 테스트 등.
